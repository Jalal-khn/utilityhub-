## What "PDF to Word" actually does

When you convert a PDF to Word format, a text-based converter reads the text of every page and rebuilds it as editable paragraphs in a .docx file. What you get is a Word document you can open in Microsoft Word, Google Docs, or LibreOffice and edit directly: change wording, fix typos, restructure sections, or copy quotes into your own work.

What you do **not** get, in a text-based conversion, is a pixel-perfect copy of the page. Tables, multi-column layouts, headers, and embedded images are reinterpreted as text flow. If your goal is to *visually replicate* the page rather than edit the text, converting to images (PDF to JPG) is the export you actually need — but a Word document is what you need when the goal is editing.

<InfoBox type="info" title="Choose the right goal">
Need to **edit the text**? Convert to Word. Need to **show the page exactly as designed**? Convert to JPG. The format you pick should match what you will do with the result.
</InfoBox>

## When PDF to Word works well — and when it hits limits

| Situation | Result |
| --- | --- |
| Text-based PDF (typed reports, Word exports, invoices) | Converts cleanly — text is fully editable |
| Multi-page documents with headings and paragraphs | Converted page by page, easy to reformat |
| Scanned or photographed pages (no text layer) | **Nothing to extract** — needs OCR first |
| Image-heavy brochures and flyers | Text extracts but images are not embedded |
| Complex tables, forms, and multi-column layouts | Rebuilt as plain text flow; rebuild layout manually |

The biggest limit is scanned documents. A scan is a photograph of a page: it contains no selectable text, so any text-based converter finds nothing. If your PDF came from a scanner or a camera, run OCR (optical character recognition) on it first to create a text layer, and then convert to Word.

<InfoBox type="warning" title="Scanned PDFs produce empty results">
If your converted Word file comes out blank, the PDF is almost certainly image-based. OCR it first, then convert again. There is no text-based converter that can read a photographed page without a text layer.
</InfoBox>

## Scanned PDFs: OCR in plain terms

When you convert a PDF and get nothing, the document is almost always a scan. Here is what is happening and how to handle it:

- **OCR (optical character recognition)** reads the pixels of a photographed page and turns them into actual selectable text. You can tell a PDF needs OCR when you try to highlight a line of text and nothing highlights.
- **Text-based PDFs** — reports, invoices, and documents exported from Word or similar — already contain a text layer and convert directly.
- **The two-step workflow for scans**: run OCR to create a text layer, then convert the resulting PDF to Word normally.

The **PDF to Word** tool converts text-based PDFs directly. For an image-only scan, add an OCR pass first, then convert again — the same file will extract cleanly once real text exists underneath.

## Troubleshooting common formatting problems

- **Text is jumbled or scattered** — multi-column PDFs extract line by line. Convert anyway and reformat into two columns in Word: Select Table or use a two-column layout.
- **Blanks, underscores, or missing spaces** — some PDFs encode spaces as gaps rather than characters. The text is present; tidy the spacing in Word with search-and-replace.
- **Tables lost their structure** — table content comes through as plain lines. Rebuild the table in Word and paste each cell; faster than retyping from scratch.
- **Different fonts expected** — extracted text uses Word's default font. Select all and apply your font to restore house style.
- **Huge PDF is slow to convert** — close other tabs so the browser has more memory, or split the PDF first with the [Split PDF](/blog/how-to-split-a-pdf) tool and convert in parts.

## Handling large and complex PDFs

In-browser conversion uses your device's memory, so the size of the PDF matters more than it would with a cloud converter:

1. **Split very large documents first** — use the [Split PDF](/blog/how-to-split-a-pdf) tool to divide a 500-page file into smaller chunks and convert each one. It is faster and more reliable than processing everything at once.
2. **Compress photo-heavy PDFs** — if the file is bloated with images, run it through the [Compress PDF](/blog/compress-pdf-without-losing-quality) tool first so conversion has less data to chew through.
3. **Close heavy tabs** — the page needs memory; free it up for smoother conversion of big files.
4. **Expect to reformat complex layouts** — multi-column and table-heavy pages come through as flowing text, so budget a little layout cleanup in Word.

None of this changes the privacy picture: every step still runs on your device, never on a server.
